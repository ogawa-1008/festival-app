# フィールドコレクション

1つの建物（号館）にはフォトスポット1つ、対戦モンスター1体を配置します。同じ会場（東京・大阪・名古屋）の異なる3校舎を回り、討伐または調査の報酬を受け取ってスタンプを3つ集めると、ステッカーを合計1枚受け取れます。

アプリでは最初にエリア（大阪・東京・名古屋）を選びます。ホームのクエスト一覧には、選んだエリアの全校舎のクエストを表示し、そのエリアの校舎のQRコードはどれでも読み取れます。ほかのエリアのQRコードは読み取れません。校舎名の地名（中目黒・心斎橋など）は、各会場の `frontend/src/data/campuses/*.ts` で号館ごとに設定します。

大阪では心斎橋1号館がリオレウス、心斎橋2号館がアルシュベルド、心斎橋3号館がメル・ゼナです。残りの配置は各会場の `frontend/src/data/campuses/*.ts` を参照してください。号館の地名（中目黒・恵比寿・五反田・心斎橋・本町・名古屋）も号館ごとにここで指定します。フィールド名（古代樹の森など）とマップの画像はモンスターから決まり、どの会場でも同じモンスターなら同じフィールドです（`frontend/src/data/monsterFields.ts`）。リオレウスは古代樹の森、ジンオウガは陸珊瑚の台地、タマミツネは緋の森、アルシュベルドは竜都の跡形、メル・ゼナは城塞高地、マガイマガドは大社跡、ナルガクルガ（東京の五反田9号館のみ）は闘技場です。マップの画像は、正式なものが届くまでどのフィールドも表示しません。フォトスポットの名称から対戦相手を生成し、1つの建物に複数のクエストを登録しない構成にしています。

討伐・調査のどちらも、その校舎のスタンプ1つとして数えます。同じモンスターへの再挑戦、練習用クエスト、別会場のクエストは追加スタンプに数えません。報酬受取前のバトル結果だけではスタンプを付与しません。

ステッカーは1種類（7匹のモンスターが描かれたもの）です。スタンプ3つがそろったら、進捗の「ステッカーをもらう」画面から交換画面へ進みます（マップ・スタンプ画面のフィールドのカードには、ステッカーの欄を出しません）。ステッカーはどの会場でも、どの号館のフォトスポットでも引き換えできます。スタンプは記録として残りますが、交換後は全校舎で追加交換できません。交換場所の校舎IDを `obtainedFieldNoveltyIds` に保存し、APIによる在庫減算に成功したときだけ受取記録を付けます。保存データに複数校舎の旧受取記録がある場合も、そのまま保持し、追加交換はできません。記録は従来どおり同じ端末・ブラウザの会場別保存データで管理します。

各クエストのQRの文字列は `QUEST_<会場名の大文字>_<号館番号>` です。例：大阪1〜3号館は `QUEST_OSAKA_1`、`QUEST_OSAKA_2`、`QUEST_OSAKA_3`。練習用の `QUEST_001` は本番用とは別です。

会場に掲示するQRコードの中身は、この文字列を末尾に付けたアプリのURL（`https://本番のドメイン/q/QUEST_OSAKA_1`）です。

- スマホの標準カメラで読むと、ブラウザでアプリが開きます。エリアを選んでいればそのクエストの確認画面へ進み、選んでいなければアプリを開くだけ（エリアを選ぶ画面）です。ほかのエリアのQRは、ホームで理由を伝えて進みません。
- アプリ内カメラでは、URL・文字列のどちらのQRも読み取れます。
- QRコードは `frontend` で `npm run qr -- --base https://本番のドメイン` を実行すると、`frontend/quest-qr/` に作られます（1枚ずつのPNG・SVGと、A4で印刷する `quest-qr-print.html`）。本番のドメインが決まってから作ってください。
- `/q/〜` のURLを直接開けるよう、Xserver（Apache）用の `frontend/public/.htaccess` と、Vercel 用の `frontend/vercel.json` で、どのURLでも `index.html` を返す設定にしています。

モンスター画像は現在ジンオウガのみ提供されています。他の対戦枠は共通のターゲットアイコンで表示します。実物ステッカーの画像は未提供のため、進捗のステッカー画面では共通のステッカーアイコンを使用します。
